## 连续听写断句提速（2026-11-05）

当前构建 near-vad-fast-endpoint-20261105。连续听写采用 near_meeting_16k 近场检测和800ms静音断句阈值；keep_dialect=false、Qwen-Audio-3.1、24kbps Ogg Opus及最终普通话输出保持原样。800ms是云端断句阈值，不是保证出字时间。下方历史版本中“1.5秒形成最终句”不再适用。

连续低电平200ms（高通后40ms帧的RMS<50且峰值<400）时，软件增益最高2倍，不硬静音、不丢帧。其余帧使用原有最高8倍防削波增益；人声增益独立保留，避免停顿后重新渐入。未调整硬件麦克风增益，轻声和较远距离识别仍需现场验证。

新增隐私友好诊断：RT_AUDIO记录音量、应用增益和低电平帧数，不记录录音或识别正文；RT_TIMING记录服务端句尾时间与收到结果时已采集音频的时间差（audio_ahead_ms），用于辅助定位断句／网络延迟，并非用户真实停顿的精确测量。

桌面端官方示例录音按实时速度上传的单次对比：旧远场1500ms约2.39秒、近场1500ms约2.14秒、近场800ms约1.40秒后收到最终结果。这是云端与桌面网络测试，不代表实板保证值。实板验证状态见FAST_ENDPOINT_VALIDATION.json。

- IP或城市变化后重新获取天气；查找／请求失败保留上次成功数据并明确标为缓存，不把旧城市数据当成新城市天气。断网也显示缓存状态。失败自动重试采用约5分钟间隔，BOOT手动刷新受60秒冷却限制。

当前映射：BOOT（GPIO0）录音、停止、发送，在新闻页刷新；KEY（GPIO18）短按翻页，长按约1秒切换问答／转文字／新闻。RX（GPIO44）短按休眠和唤醒，长按约3秒进入手机网页配网。下方早期按键说明以本节为准。外接到相同 GPIO 的按键同步对换功能。

## 手机网页配网与 RX 休眠键（2026-11-05）

此节为当前操作方式；下方早期记录保留开发历史。

- 短按外接 RX（GPIO44）键：进入浅睡眠，屏幕清空、Wi-Fi 和麦克风暂停；再按一次同一键唤醒，恢复原页面及文字，重新连接 Wi-Fi。唤醒这一按只用于唤醒。
- 长按 RX 约 3 秒：进入手机配网。屏幕显示 RLCD-Setup 热点名称、每次随机生成的密码和地址。
- 手机在系统 Wi-Fi 设置中连接该热点；遇到“无互联网”提示时选择保持连接。浏览器打开 `http://192.168.4.1`，选择或输入家里的 2.4GHz Wi-Fi，填写密码，点击“连接并保存”。无需电脑或重新刷机。
- 成功连接后才将 Wi-Fi 保存到板上 NVS，约 10 秒后关闭热点。失败约 30 秒后恢复原配置，可重试。短按 RX 可退出配网。开机或唤醒后持续断网约 45 秒且空闲时，也会显示配网入口。
- 配网期间暂停开始录音及新闻刷新。正在录音、连续听写或联网请求时，RX 休眠/配网操作不执行；先用 BOOT 停止听写并等待处理结束。
- BOOT（GPIO0）录音/停止、KEY（GPIO18）翻页及长按切换、问答、连续转文字、新闻及四键测试保持原功能。

GPIO44 不具备深度睡眠唤醒能力，因此这里使用保留 RAM 的浅睡眠，电源仍处于 ON。睡眠时不联网更新新闻，唤醒后按原规则补更新。没有实测电流，不将此模式视为彻底断电。Wi-Fi 配置保存在独立的 rlcd-net 命名空间，API Key 与新闻缓存保持原存储；LocalConfig.h 中的原 Wi-Fi 仅作为无保存配置时的初始值。

诊断串口命令：`wifi-setup` 进入配网，`wifi-cancel` 退出，`wifi-info` 显示不含密码的状态；`sleep` 实际睡眠，`sleep-test` 进行 3 秒定时唤醒测试，`sleep-info` 查看最近唤醒原因。休眠时电脑串口会断开，唤醒后会自动重新枚举；串口工具需要重新打开 COM 口。串口和网页均不提供读取 API Key 或已保存 Wi-Fi 密码的接口。

目标板：微雪 ESP32-S3-RLCD-4.2，ESP32-S3 N16R8，4.2 英寸 300×400 反射式 LCD，板载 ES7210 双麦克风。本工程独立于旧灯控屏工程。

当前默认为“千问问答”：按一下 KEY（GPIO18）开始录音，说出问题，再按一次结束；最长 20 秒自动结束。普通话或上海话经 qwen3-asr-flash 识别后交给 qwen-flash 回答，屏幕显示“问”和“答”。每次为独立提问，暂不记忆上一轮内容；已启用阿里云联网搜索，查询结果仍须注意日期、地点和来源。

短按 BOOT（GPIO0）在长结果中翻页，末页后返回首页。在空闲或结果页面长按 BOOT 至少一秒，切换“千问问答”和原来的“转文字”模式；录音、请求期间不能切换。重启恢复问答模式。

“转文字”保留原功能：把上海话、吴语口语转换为意思相同的标准普通话，普通话输入仅整理标点，此模式不回答问句。失败时明确显示错误。语音识别本身的误差可能影响转换或回答。

录音只在 RAM 中暂存，不写 SD；会上传给所配置的阿里云接口。不是持续监听或边说边显示文字。仍使用原有本地 Wi-Fi 和 API Key，不需要重新填写。

## 编译

Arduino-ESP32 3.3.3，库依赖 U8g2、ArduinoJson。厂商显示驱动及 ES7210 codec 依赖已随项目附带。

## 硬件与数据路径

使用厂商 U8g2/ST7305 驱动横屏 400×300 显示；字体为 U8g2 的文泉驿 16 像素 GB2312 字库，少见方言字、生僻字可能缺字。ES7210 I²C SDA13 / SCL14；I²S MCLK16、BCLK9、WS45、DIN10。输入 16kHz、16bit 双声道，第一版选择 MIC1 生成单声道 WAV。麦克风增益 24dB，去直流分量。未启用双麦降噪/AEC，不使用扬声器。录音缓冲和 Base64 请求体放在 8MB PSRAM，HTTPS 验证根证书并等待网络校时。

串口 115200 输出 `[MIC]` 初始化、录音样本数/RMS/削波数和 `[ASR]` 结果长度/耗时，不输出密钥或上传音频。`HTTP 401/403` 优先检查密钥、地域及模型权限；网络与 TLS 超时、录音过短、音量过低分别显示错误。自动重连 Wi-Fi，不自动重新上传失败的录音。

## 验收步骤

1. 屏幕正确显示中文标题，串口出现 ES7210 与 PSRAM 就绪。
2. 普通话说“今天是星期三，我想把说的话显示在屏幕上”，检查文字和标点。
3. 用自然上海话说一段熟悉句子，再尝试普通话/上海话切换，记录误识别词。
4. 检查长文字翻页，KEY 可开始下一次录音；Wi-Fi 断开能报错；短录音和 20 秒上限行为正常。
5. 检查 RMS 与削波数据，实测后再调增益及输入通道。编译通过不代表这些实板测试已通过，实际结果另存 BUILD_RESULTS.json。
