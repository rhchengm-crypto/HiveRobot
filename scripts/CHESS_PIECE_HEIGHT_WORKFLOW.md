# 棋子真实高度辅助识别

当前版本 `v2.7-metric-height-assisted-yolo` 完成采样、三维估高、高度模型建立、
验证报告和在线辅助识别。支持所有黑白 12 类，不需要重新训练 YOLO。

## 部署

将以下文件放到 Orin 现有 Web 脚本同一目录，保留现有依赖文件，重启原服务并刷新网页：

- chessboard_vision_v2_7_web_control.py
- chess_piece_yolo_infer.py
- chess_piece_height_samples.py
- chess_piece_height_model.py（新增）
- chess_piece_height_web.py（新增）

继续使用当前 best.pt。高度数据在 YOLO 数据集旁边的 `chess_piece_heights` 目录。

## 1. 标定深度棋盘平面（首次或相机/棋盘移动后）

1. 清空棋盘，保持相机静止。
2. 在主页面 Height Samples 区域点 **高度标定 / 建立高度模型 / 验证报告**，
   或访问 `http://<orin-ip>:8097/height-setup`。
3. 点击 **冻结空棋盘**。页面将深度图叠加在 RGB 上，可调整透明度。
4. 调整深度层横纵缩放、水平和垂直平移，检查空棋盘四边是否同时重合；
   初始适配显示不代表配准完成。确认对齐后，在 **RGB** 上依次点 a1、h1、h8、a8
   对应的棋盘 8×8 区域四个外边角，不包含木框，不是四个格子中心。
   可撤销上一角。程序按叠加变换将 RGB 点击换算回深度坐标。
   若四边不能同时对齐，不要勾选确认，需要相机 RGB/深度配准参数。
5. 检查内参：程序尝试从深度 topic 同级 `camera_info` 读取；
   如果 K 中焦距为 0，请填入相机真实深度内参，不能猜值。
   JSON 中 width/height 必须对应深度图，K 为九个数，D 为镜头畸变系数。
6. **已有旧高度样本**：只有采样时相机、棋盘和分辨率与当前完全一致，才勾选复用确认。
   旧数据没有三维标定编号，因此不会被静默当作兼容数据。
7. 点击 **保存三维标定**。角点需在冻结后 3 分钟内保存，超时重新冻结。

程序检查有效深度、平面内点比例，以及三维边长是否接近项目配置的 440mm。
失败时修正原因后重试。若实际棋盘尺寸不是 440mm，需先修正全项目棋盘尺寸配置。
手动叠加仅用于当前空棋盘平面角点选择，不是通用三维相机配准。
后续 RGB 与深度通过各自棋盘坐标，按同名格子关联。

## 2. 采样或复用

原有 RGB/depth 高度样本可以在同一配置确认后重新计算，不必因为算法升级重拍。
新样本保存时自动估高；尺量高度现在是**可选的校验值**。
每类至少提供一次尺量校验，建议不同格子都做校验，以判断高度测量误差。
同类不同实物有尺寸差异时填写实物编号，避免混淆。

保存的 `sample.json` 包含自动估高、三维标定编号、有效性与错误原因。
即使当前不能自动测量，也会保存原始数据并明确标记原因，不会写入虚假的高度值。
原图保存为 rgb.png，原始深度为 depth.npy；与 YOLO 标注数据独立。

## 3. 建立并验证高度模型

点击 **建立高度模型并验证**（不是 Start YOLO Train）。

- train 建立各类别的测量高度范围。
- val 检查范围是否适用，尺量标签检查测量误差。
- test 只报告估高误差与高度候选，不参与拟合或启用决策。
- 每类至少 2 份有效 train、1 份有效 val，以及至少一次尺量校验。
  这是功能启动下限，不代表这些数量足以证明现场可靠性。
- 未通过深度质量检查的样本列入 skipped_samples，附具体原因。
- active_classes 表示通过当前验证门槛的类别；class_status 列出全部 12 类状态。

结果写入 `height_model.json`。新增样本后再次点击建立，重新标定后也要重建。
验证集和测试集应来自独立摆放，避免连续重复图混入不同集合。

## 4. 直接识别

回主页面点击 Inspect Square / Detect Whole Board / YOLO Detect Table。
两路检测入口均使用**与 RGB 检测输入同次捕获的深度帧**，不使用推理结束后的新深度。
图上显示 `H=...mm`，JSON 每格的 height 字段记录估计值、方法、候选及是否改判。

只有原类别和替代类别都通过验证、同阵营候选唯一、测量排除原类别且留有误差余量时，
才改判。例如 RGB 预测 pawn，但测高明显只支持 bishop，可以标记 height_assisted_yolo。
改判不会把 RGB 原分数伪装成新类别概率，图上保留原 RGB 类别和分数。
高度范围重叠、类别未验证、无有效顶部深度、时间不同步或标定失效时保留 RGB 判断。

## 算法和限制

深度像素按深度内参和畸变参数还原到光学坐标系；空棋盘用鲁棒平面拟合。
棋子高度是三维点到棋盘平面的垂直距离，使用连通主体的第 98 百分位抑制孤立飞点。
按三维投影到底面的棋盘坐标分格，所以没有把 `median_raise_m` 直接当作真实高度。
顶部被遮挡、深度边缘缺失、反光和相邻棋子粘连仍会影响测量；无法保证所有视角都可用。
三维测量和范围门槛需用实际数据验证，合成测试通过不等于现场精度已得到验证。

缺少内参/标定时识别会继续运行，并在 height.reason 中说明原因。
若 camera_info 不在默认同级 topic，可按实际驱动配置修改订阅路径或在标定页面填真实内参。
