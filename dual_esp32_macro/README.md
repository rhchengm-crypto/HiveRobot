# 双 ESP32：9 个按键 + 1 个电位器

2026-10-23，协议版本1，保留冷启动恢复v2。当前版本已替代五键一字节协议，两块板这次必须一起更新。

## 当前版本快速说明

- 副板固定负责9键独立消抖和GPIO34电位器采样，只上报输入，不保存宏映射、音量用途或界面逻辑。
- 主板负责宏按下/释放回调、电位器方向/用途映射，以及显示、触摸。以后正常更改用途只需改主板；保持协议版本1、地址0x42、8字节帧和现有接线，就不需要为宏映射重刷副板。
- 冷启动恢复保留：主板1000ms等待、地址探测后20ms等待、离线5秒受限总线恢复；副板300ms稳定等待、初始化失败重试、3秒无请求后外设恢复及15秒退让。
- 主板参考界面显示3×3九键、电位器进度条和触摸状态，串口115200输出[KEY]、[POT]、[HEALTH]。
- 固件：macro_main/macro_main.ino、macro_secondary/macro_secondary.ino。所有同目录.h/.cpp要保留。
- 固定协议见PROTOCOL_V1.md；以后主板集成见INTEGRATION.md。
- 已验证五键冷启动版本备份：桌面 dual_esp32_macro_5key_coldstart_v2.zip。9+1版必须重新做上板验证，不能继承五键版本全部测试结论。

### 实板验证

1. 断开两板连接，分别烧录本次主/副程序；烧副板时避免主板5V与副板USB同时接入。完成后拔副板USB，再恢复已验证接线。
2. 整机断开USB和电池，等待数秒再上电，不按副板Reset；重复5次，确认ONLINE。
3. K1~K9逐个按下/松开，每次仅一个PRESS/RELEASE。K9单独按下held应为0x100；K1+K3为0x005；九键全按0x1ff；全部松开0x000。
4. 旋转电位器应出现[POT] raw=... value=... percent=...，数值连续随位置变化。raw是滤波后的12位ADC读数，不是电压，也不是旋转步数。主板默认抑制小于32计数的变化，最多约50次/秒上报旋钮事件；不旋转时少量ADC噪声属正常。
5. 测试同时按多键并转动电位器，观察errors/overflows是否保持不增长；测试触摸仍能响应。
6. USB和电池模式都测试。断开I²C后主板100ms超时释放按键，恢复后自动上线；离线时旋钮显示保留最后数值，不表示当前传感器仍在线。

## 硬件核对与详细说明

以下电源和板型依据沿用已核对资料；当前数据格式统一为PROTOCOL_V1.md定义的8字节帧。

## 1. 电源核对结果：不要把 VIN 名字当成输出保证

已查看厂商资料包里的 Type-C 原理图、Type-C 规格书，以及 FM5324HJ1 官方数据手册。旧的 Micro-USB 布局图没有这套充放电电源，不能用它推断 Type-C 电池供电路径。

Type-C 资料包的原理图文件标题沿用了 `ESP32-2.4TFT`；因此它只能证明该图的网络连接，不能替代对用户实板版本的核对。配套 Type-C 规格书明确是 3.5 英寸、ST7796、320×480、有锂电池接口。接线前按下面步骤确认实板网络，尤其 P1 的版本差异。

FM5324HJ1：1脚 `VIN` 是输入，6脚 `BAT` 是电池，7脚 `SW` 接电感，8脚 `OUT` 是输出。板图中：

```
主板 USB-C VBUS -> 输入 +5V -> FM5324 VIN(1)
主板 BAT1/BAT+  -> FM5324 BAT(6) 与电感
                              |
                     FM5324 OUT(8) -> V_OUT -> 主板自身3.3V稳压器
                                         |
                                         +-> 副板 5V / VIN
共同 GND ------------------------------------> 副板 GND
```

输出 `OUT/V_OUT` 才是本方案使用的受管理电源：USB 供电时由芯片输出通路供电；拔掉 USB 后由单节锂电池升压供电。启动/待机时可能需要短按主板电池电源键。芯片的额定输出能力不是整块板能保证留给副板的余量，需做带载测试。

### 精确电源接线表

| 主板物理位置/网络 | 连接到副板 | 说明 |
|---|---|---|
| **FM5324 OUT（8脚）同网的输出滤波电容电源端**，图中为 **C18/C21 的非 GND 端，网络 `V_OUT`** | **5V / VIN** | 推荐从较大的电容焊盘引线，不从细小芯片引脚直接飞线；不加外部稳压器 |
| 主板 **P1/GND 或 P3/GND** | **GND** | 电源和 I²C 共地 |
| 主板 **BAT1 的 BAT+、BAT-** | 仅接 **单节 3.7V 18650 电池的正、负极** | 按板上极性确认，不依赖连接线颜色；不接副板 VIN |
| 主板 **P1/VIN** | **暂不接副板电源** | 所核对 Type-C 图接的是输入侧 `+5V`，与 `V_OUT` 不同，不能保证电池模式有5V |
| 主板 **3V3** | 只接 I²C 上拉电阻上端 | 不把主副板 3V3 电源输出直接并联 |

如果实板修订版的 P1/VIN 在仅电池模式下仍有稳定约5V，而且断电测量确认与 FM5324 OUT 是同网、不是 BAT/SW，可以直接用 **P1/VIN → 副板5V/VIN**，不需要焊接电容端。未确认前按上表使用 `V_OUT`。没有实板测量，不能保证用户那块板 P1/VIN 的电池模式输出。

不要从电感的 SW 开关节点取电；不要接原始电池 3.0~4.2V 到副板5V/VIN。副板使用其板载3.3V稳压器，主板 FM5324 已有充放电/升压功能，不加不必要的外部模块。

## 2. I²C 与九键接线

I²C 为 3.3V 逻辑，主控 master、从控 slave=0x42，400kHz。使用板上丝印确认脚位，不按照片中插头朝向猜引脚序号。

| 信号 | 主板连接器/丝印 | 副板丝印/GPIO |
|---|---|---|
| SDA | **P3 / IO21**，或有该标注的 **CN1 / IO21** | **21 / GPIO21** |
| SCL | **P3 / IO22**；部分 Type-C CN1 也引出 IO22，但旧版 CN1 该位是 NC | **22 / GPIO22** |
| 共地 | **P3 / GND** | **GND** |
| SDA 上拉 | SDA 经一只 **2.2kΩ** 到主板 **3V3** | 整条总线一组即可 |
| SCL 上拉 | SCL 经一只 **2.2kΩ** 到主板 **3V3** | 不能上拉到5V |

参考图 CN1 的 IO21 已有4.7kΩ上拉；外加2.2kΩ后等效约1.5kΩ，仍为合理3.3V上拉。GPIO22 也要有上拉，不依赖 ESP32 弱内部上拉在400kHz下工作。两板放在同一机壳内，连线尽量短，初始测试约10~20cm。

九键与电位器的完整GPIO表见本页顶部。按键均为副板INPUT_PULLUP接地输入，独立接线，不是矩阵，不存在矩阵鬼键。GPIO34为ADC1电位器滑动端，不加上拉。

主板请求固定8字节：标识、版本、九键位图、电位器滤波值、序号与CRC，详见PROTOCOL_V1.md；不能继续按旧版读取一个字节。

## 4. 固件调度与故障处理

- 从板每1ms扫描9键，每键独立非阻塞10ms消抖，支持任意同时按键。
- I²C onRequest 只在极短的ESP32跨核临界区复制8字节快照，再向 Wire 缓冲区写入8字节；临界区内不执行任何外设I/O，不扫描、不打印、不执行宏、不延时。
- 原始ESP32的从机TX FIFO需要预装载，按官方API初始化一次；回调填充下一响应。因此状态可能晚一个轮询周期，不保证每次读的是同一瞬间 GPIO 电平。
- 主控正常约2ms读取；I²C超时2ms。连续5次失败后退让到20ms，恢复后回到2ms。
- 100ms无有效包会释放已按住的键并显示OFFLINE，避免宏/修饰键卡住。
- I²C任务不画屏幕，不执行宏。UI循环处理事件，参考界面最多20Hz刷新、每10ms读取触摸；宏回调应快速入队。
- 64快照队列保留正常多键变化；溢出显式计数并释放/同步状态，长时间阻塞时不声称所有短按都能保留。
- 正常输入路径预计约10~15ms量级（消抖+扫描+轮询），这不是已经实测的端到端延迟；参考屏幕状态显示另受50ms刷新周期影响。

## 6. 实际上电测试

1. **先单独烧录副板。** 此时主副板供电线和I²C线均断开。副板USB接电脑，串口115200应显示 `Secondary ready`。完成后拔掉副板USB。
2. **单独烧录主板。** USB-C供电，串口115200，屏幕应出现九键及电位器页；未接副板时显示OFFLINE，触摸计数仍应可增加。未看到画面不代表程序未运行，先查看串口并确认ST7796板型。
3. **确认电源节点。** 副板未接，主板USB供电时测 `V_OUT` 对GND约5V；拔USB、接单节18650，必要时短按电池键，再测同一节点应仍约5V。另测P1/VIN，不要把只在USB下有电的节点当输出。断电后用通断档确认所选输出焊盘与OUT(8脚)同网，与GND不短路。
4. **断电连接。** 将V_OUT/GND接副板5V/GND；接GPIO21、22及两只3.3V上拉；接九个开关。副板USB保持拔下，避免两个5V电源并联或反灌。
5. **USB模式。** 仅插主板USB-C；两板启动，主屏应ONLINE。逐键按下/松开，串口每个边沿应只记录一次，长按不反复触发。
6. **组合键。** K1+K3应显示held=0x05，全按为0x1ff；按住K1时反复按K2，K1不能意外释放。松开全部为0。
7. **触摸与断线。** 按住键的同时触摸屏，观察触摸计数继续变化。断开副板SDA或断副板供电，约100ms后所有已按键应释放、UI仍可运行；复原后自动ONLINE。不要在测量电源时短接相邻引脚。
8. **电池模式。** 拔主板USB-C，只留18650，必要时短按电源键；重复全部按键和触摸测试。带载测副板5V应稳定，监视brownout/reset。FM5324输入断电会转升压，但实际切换是否造成瞬时复位需实测，不能仅凭芯片功能承诺无缝UPS。
9. **负载测试。** 分别在USB、电池模式连续运行15分钟，检查两板稳定及电源温升。若实际原应用启用Wi-Fi/BLE，必须在相同负载下重测。低背光/休眠后负载很小时，芯片的轻载关机配置可能触发自动关机，按电池键唤醒；常见手册值约80mA、32秒，实板子型号可能不同。

上面是待执行的实板步骤，当前没有声称已完成USB/电池、触摸或双板联调，也没有自动烧录未知端口。

## 冷启动恢复修复 v2（2026-10-23）

实测反馈：两板共同上电时OFFLINE，副板手动Reset后ONLINE。此现象提示供电启动/从机初始化/总线状态问题，不足以断言是哪一种。

本次修改：

- 主板I²C轮询任务先等待1000ms，给副板电源、启动和TX预装载留出时间；此等待不占UI任务。
- 未连接时先探测0x42，得到ACK后等待20ms再读，避免过早要求副板发送。正常连接仍按约2ms读取。
- 连续离线时每5秒最多恢复一次主板I²C：结束驱动、用开漏方式清总线（SCL可释放时最多9个时钟和STOP）、重新初始化；SCL被外部持续拉低时不会强行推高。
- 副板先等待300ms，再初始化；总线忙或初始化失败不再永久停止，每秒重试。
- 副板连续3秒没有请求回调会重新初始化I²C和TX FIFO，不重启CPU；前三次最短间隔3秒，其后最短15秒，避免持续重启外设。正常扫描/消抖逻辑保留。
- 新增副板[BOOT]/[SLAVE]日志，主板[I2C]日志包含地址探测结果、字节数量与SDA/SCL电平。probe=255表示该轮未进行地址探测，不是实际地址错误码。

必须两块板都重新烧录。测试时不要手动按副板Reset：断开主板USB和电池，待两板完全断电数秒后再接主板电源；等待约10秒，至少重复5次，分别测USB和电池供电。主板应自动ONLINE且按键能用。

如果副板完全没有[BOOT]日志，或反复出现brownout/reset，本修复无法代替对5V/3.3V及EN启动电路的检查。请保留原始启动日志，不要只看HEALTH。即使v2编译通过，也必须通过上述冷启动实测后才能确认修复。

备份位于各修改文件旁：.bak-before-cold-start-20261023。

## K7 引脚替换（2026-10-23）

用户反馈同一开关接K2正常，接GPIO19换线后仍无反应。尚不能仅凭这些测试确认GPIO19硬件损坏；为绕开该路径，将副板K7由GPIO19改为GPIO33。其余键、GPIO34电位器、协议V1及冷启动恢复v2不变。主板无需更新，副板本次需要重新烧录；K7信号线移到副板GPIO33，开关另一端仍接GND。正常日志K7 PRESS/RELEASE，K7单按held=0x040。GPIO19不再用于按键。

## 主板旋钮防抖（2026-10-24）

仅更新主板，副板源码/固件和协议不变。主板ADC通知门槛由8增至32；应用侧PotControl按0~100档量化，在档位边界增加约20 ADC计数的滞回，端点16计数范围吸附到0/4095。只有档位实际变化才打印[POT]并执行其后的应用动作，界面也只随档位更新。首次上线会输出一次初始位置。HEALTH仍按原周期输出，不代表旋钮移动。
