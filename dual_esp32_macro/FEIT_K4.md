# 主板 Feit 云端直连控制（K4）

仅更新主板 macro_main。副板软件、固定 8 字节 I²C 协议、九键引脚、电位器滤波、冷启动恢复保持不变。

## 使用

- K4 每次按下切换当前配置 Feit 灯泡的开/关；松开、持续按住不重复触发。
- K4 仍接副板 GPIO26 与 GND，不使用主板 GPIO4，不需要增加线路。
- 控制对象沿用 feit_bulb_direct 中的单个设备，并非枚举家庭内所有灯泡。
- 屏幕 WiFi 表示联网情况；FEIT ON/OFF 是最近查询或云端接受的状态；BUSY 表示正在请求。
- 开机在后台联网、NTP 校时、获取 Token、查询初始开关状态；触屏及 I²C 持续运行。
- 连网后正常按 K4，观察 `[FEIT] K4 -> target=ON/OFF` 与 `result=OK`，并检查实际亮灭。
- 外部 App 改灯后，用串口 `status` 同步状态；正常按键不逐次查询状态。

## 串口 115200，换行发送

`on`、`off`、`status`、`bright 10-1000`、`temp 0-1000`、`color h s v`。
色彩范围 h=0..360、s=0..1000、v=10..1000。原直连版指令语义保留。

## 实现

FeitCloud 后台任务位于 core0、优先级1、栈16KB，I²C 任务仍优先级2；UI 回调只入队。
队列最多8条，满时记录未入队；超过30秒未开始执行的命令丢弃，避免断网恢复后执行积压动作。
保留原版 CA 证书校验、主机名/SNI、HTTPS 连接复用、Token 缓存、DNS/TCP/TLS 分段计时。
仅连接建立失败且尚未发送 HTTP 时重试一次；发送后响应不明的 POST 不自动重发。
没有重新引入此前失败的 DNS 缓存或 TLS 会话恢复。
联网中断会关闭旧连接、使状态缓存失效；下次切换先恢复状态。
原 Wi-Fi 和 Tuya 配置已复制至本地主板 `FeitSecrets.h`，不需要重新输入；原 direct 工程未修改。

## 编译/烧录和验收

Arduino-ESP32 3.3.3，ESP32 Dev Module，4MB，默认分区；依赖 ArduinoJson、Adafruit GFX/BusIO。
打开 macro_main/macro_main.ino，只烧录主板。副板不烧录。

1. 主副板一起冷启动，确认 SLAVE ONLINE，九键日志和电位器、触摸均正常。
2. 等待 `[FEIT] Startup state ON/OFF`，按 K4 两次，确认灯泡开关跟随且屏幕保持响应。
3. 长按 K4 2秒，确认只产生一次请求；测试 K4 与其他按键同时按，其他事件仍能上报。
4. 串口发送 status/on/off 验证；空闲几分钟再按 K4，查看重连计时。
5. 暂停路由器后检查触屏和按键仍响应；恢复联网后重新按 K4 验证恢复。
6. USB 与电池各做一次冷启动、开关灯测试。

当前仅完成代码编译与静态逻辑验证，未烧录或验证这次主板的实际云端/灯泡通信。
