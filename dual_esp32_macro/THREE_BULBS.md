# 三灯控制：K9 / K8 / K2 单控，K4 总控，旋钮统一亮度

| 控件 | 灯泡/功能 |
|---|---|
| K9（副板GPIO32） | 原 Feit 灯泡，BULB1 |
| K8（副板GPIO23） | second room c2，d8:fc:92:e4:98:37，192.168.0.89，BULB2 |
| K2（副板GPIO14） | 新增 second room c1，d8:fc:92:e4:85:a7，192.168.0.249，BULB3 |
| K4（副板GPIO26） | 任一灯开着则全部关；三灯都关则全部开 |
| 旋钮 | 为三灯设置同一亮度目标，10..1000，最低1%到最高100% |

只刷主板 macro_main，副板和接线不变。每次按下触发一次，长按/释放不重复触发。
第三只灯已通过现有Tuya项目的MAC精确匹配，Device ID为 `REDACTED_LOCAL_DEVICE_ID`。查询时在线，已读取开关及10..1000亮度功能定义；配置已写入本地FeitSecrets.h，无需补填密钥。
仍走云端HTTPS，局域网IP用于设备记录，不建立本地控制连接。

每灯各自保存开关状态、亮度待发值；后台轮流处理最新亮度，不积压旧旋钮位置。
关灯时只保留该灯的最新亮度，开灯成功后再应用，不强制开灯。开机首次旋钮读数仍只作基线。
旋钮仍调白光bright_value_v2，不主动切换颜色模式。HTTPS顺序下发，三灯实际变化可能略有先后。
K4逐灯记录成功/失败；某一灯失败仍尝试其余灯。如果状态未知且查询失败，则取消本次总控，单灯键仍可单独操作。
外部App改开关后可用串口status/status2/status3重新同步缓存。

串口115200：原灯 on/off/status/bright；第二灯 on2/off2/status2/bright2；第三灯 on3/off3/status3/bright3。bright后接10..1000。temp/color仍针对原灯，lcd保留屏幕恢复。
屏幕显示K9/K8/K2各自的缓存状态；?表示未知。云端接受不是物理光输出确认。

上板验证：
1. 只烧录主板，确认屏幕、触摸、I²C冷启动恢复正常。
2. 按K2两次，新灯应独立开/关，其余灯不变；复测K8/K9。
3. 三灯都关时按K4应全开，再按应全关。混合开关状态时按K4应全关。
4. 三灯都开时调旋钮，观察BRIGHT bulb=1/2/3目标及accepted日志，确认最终亮度跟随同一目标。
5. 关一灯后调亮度，该灯保持关闭，其余两灯正常调光；再打开该灯后检查最新亮度应用。
6. 快速转动后停住，确认最终值跟随且不连续执行旧值；USB/电池各做一次冷启动。

编译包含三灯全部8种开关组合/未知状态、三个亮度槽相互独立/延后发送/取消测试，以及原输入/CRC/滤波测试。
本次未烧录，三灯硬件测试待完成。之前两灯版本已由用户确认可用。
