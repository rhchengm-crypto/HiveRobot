# SD 狗狗动画

2026-10-24：本对话版本已刷入 COM4 主板，SD 素材已传入并校验。副板不更新。

- 开灯：沿用原狗狗，约每 4.8 秒眨眼一次，配合轻微起伏；三只狗错开时间。
- 关灯：原睡觉图与吸气变化帧交替，0～2 像素轻微呼吸，约 3.2 秒一个周期。
- 只刷新 128×108 的狗狗区域；九键页和触摸校准时暂停。触摸按住时优先处理操作。
- 保留三灯独立/总控、K1/K6 配色、旋钮调光、K7/K5 翻页，以及原触摸边界、防重复与 NVS 校准。
- 无卡、缺素材或帧校验失败时使用原静态图。启动只挂载/读取，不运行写入检测，不格式化 SD。

## 素材

SD 实际文件：`/dogs/animation.dga`，166,480 字节。主板 CLK18/MISO19/MOSI23/CS5，独立 VSPI 4MHz。
电脑副本：`sdcard/dogs/animation.dga`，制作源文件在 `assets/dog_animation/`。
包中有三只狗的开灯/睡觉状态，每种含原图和变化帧，共 12 帧；原六张静态图逐字节保留。
包头、调色板、每帧均有 CRC32；上传另验证整包 CRC。每次只读 512 字节，使用一个 13,824 字节帧缓冲。
播放按需从 SD 读取，不将整包常驻内存。

原画与变化帧使用内置 image_gen，变化帧完整提示词在 `assets/dog_animation/PROMPT.txt`。
`tools/generate_dog_animation.py` 可用 `.deps` 中 Pillow 重新编码。
`ui_preview/dog_animation.gif` 是实际像素素材的动画预览，并非主板录像。

## 更新素材与诊断

关闭串口监视器后运行：

```
python tools/upload_animation.py --port COM4
```

上传工具依赖随项目保存的 `.deps/serial`（pyserial 3.5，BSD），不需要全局安装。
上传分 512 字节确认，只修改 `/dogs/animation.tmp`、`animation.dga`、`animation.prev`。
校验完成再替换；保留上一份。断电若发生在改名间隙，下次启动可恢复 `.prev`。

串口：`dogstatus` 查看播放/内存状态，`dogverify` 分段验证全部帧。
`sd` 保留手动读写检测，用前关闭动画文件，用后重新加载；正常启动不执行它。
`lcd` 仍为原屏幕恢复命令。只更新 app 区域可保留 NVS；本次未擦除触摸校准。
更新主板使用 Arduino IDE/CLI，或将 `firmware/macro_main/macro_main.ino.bin` 写入 0x10000；副板不刷。

## 实测

编译通过：1,253,703 / 1,310,720 字节程序，64,184 字节静态 RAM，默认分区。
应用刷入并校验哈希；素材整包 CRC edd0d04f，全部 12 帧 CRC 通过。
重启从 SD 重新加载、持续动画绘制、LCD 恢复后继续播放、错误长度上传拒绝均通过。
实测最大分段读取约 11.2ms，最大狗狗区域绘制约 14ms；串口错误数 0。
控制后端、按键/旋钮模块及触摸处理函数与前版核对一致。
未通过肉眼观察屏幕或自动操作实际触摸/灯泡来验证；请实板确认外观与操作手感。

原项目源码备份在 `backup-before-sd-animation/`；并发对话产生的另一套实现已快照保存，未覆盖丢失。
完整 Flash 备份和刷入/上传/实测日志保存在本对话 work 目录。
