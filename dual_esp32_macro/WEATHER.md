# 三页界面与 98074 天气

本版已刷入 COM4 主板。副板不更新。页面顺序固定为：

1. LIGHTS：原三灯控制和 SD 狗狗动画。
2. WEATHER：98074（Sammamish）今天起三天的预报。
3. 9 KEYS：原九键和电位器诊断页。

顶部三张 144×36 标签支持触摸，K7/K5 向左/右翻页，在两端停止。
原灯控卡片的触摸范围、防重复、NVS 校准与按键映射保留。九键页只移动位置。

## 天气

使用 ZIP 区域坐标 47.6254, -122.0462，Open-Meteo Forecast API。
按 America/Los_Angeles 当地日界显示今天起三天的日期/星期、天气图标、最高/最低摄氏温度及最大降水概率。
页面同时显示预报来源、获取时间、PST/PDT 时区与更新/缓存/离线提示，不用占位数值冒充天气。
温度按整数显示；API 原始浮点值保留在数据结构中。

通常每 30 分钟刷新；跨当地午夜时约一分钟内重取。失败间隔一分钟重试。
触摸 REFRESH 可请求刷新，至少间隔 15 秒；按键、旋钮或触摸活动后推迟 5 秒开始天气请求。
上次成功的完整预报保存在独立 NVS 命名空间 weather98074/forecast1，含格式标记、邮编和校验。
启动可显示缓存；请求失败不会部分覆盖旧数据。日期过期或断网会明确标注，仍显示实际预报日期。
触摸校准的 NVS 命名空间不变；SD /dogs/animation.dga 未修改。

天气 HTTPS 验证 ISRG Root X1 证书。为适应 ESP32 内存，天气只在原网络工作线程的灯控队列和调光队列均空闲时运行；先释放闲置 Tuya TLS 连接，再建立天气连接。
天气获取不在 UI/触摸循环中运行。请求期间新灯控命令会短暂排队，取完天气即恢复处理；下一次 Tuya 请求会重新建立连接。
没有另外增加占内存的天气网络任务。

## 串口诊断

- weather：打印缓存/更新状态和三天预报。
- weatherrefresh：请求刷新。
- page 0 / page 1 / page 2：分别显示灯控、天气、九键页。
- lcd、dogstatus、dogverify 及原灯控命令保持可用。

## 编译与实测

Arduino-ESP32 3.3.3、ESP32 Dev Module 默认分区：程序 1,284,243/1,310,720 字节，静态 RAM 64,840 字节。
应用已写入 0x10000 并验证哈希，未整片擦除。
实测通过：主板从 Open-Meteo 获取实时三天数据；三页顺序；离开灯控页暂停动画、返回恢复；后台刷新时串口 UI 循环响应；天气页 LCD 恢复；重启读取 NVS 天气缓存。
三标签/刷新按钮的边界、非灯控页不能触发灯卡、日期/闰年检查均由编译期断言验证。
灯控命令 switch 和 16 个灯控/动画/硬件源文件与前版比对一致。
实际天气页外观、物理触摸和真实灯泡响应仍需实板观察；预览 ui_preview/weather.png 不是硬件截图。

源码备份：backup-before-weather。更新前应用备份保存在本对话 work/weather/application-before-weather.bin。

数据与说明：https://open-meteo.com/en/docs 。ZIP 坐标：https://api.zippopotam.us/us/98074 。
