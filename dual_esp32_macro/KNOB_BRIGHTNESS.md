# 旋钮调节 Feit 亮度

只更新主板，接线与副板软件不变。K4 按下切换开/关，旋钮控制原 Feit direct 的 bright_value_v2 白光亮度，范围10..1000（灯泡最低亮度1%，最高100%）。最小位置不会关灯，关灯用K4。

保留旋钮滤波、迟滞、屏幕恢复及冷启动恢复。上电的首次旋钮读数只作为基线，不覆盖灯泡当前亮度；需要转动旋钮才发出亮度控制。

操作行为：
- 转动后停稳150ms提交最新位置，连续旋转时约每1秒提交一次最新值。
- 两次旋钮请求开始至少间隔750ms；始终只有一个待发送最新值，中间位置合并。
- 正在等待 HTTPS 时的新位置保留为下一次目标，不会塞满普通命令队列。
- K4和串口命令优先于待发旋钮请求；已在执行的 HTTPS 无法抢占。
- 灯关着时只保存最新旋钮位置，不强制开灯；K4开灯成功后应用该位置。
- 若亮度请求失败，不循环重发；下次转动再提交。云端通信本身仍可能有秒级延迟。
- 原有串口 bright 10-1000 仍可用，并取消尚未发送的旧旋钮目标。
- 屏幕 BRIGHT 显示旋钮目标值，不代表云端已接受，也不代表光输出实测结果。
- 若已通过外部App切到彩光模式，需要先回白光模式；此控制沿用原 direct 的白光亮度指令，不主动改变颜色模式。

验证：
1. 只烧录 macro_main，等待联网和屏幕恢复，确认九键/触摸正常。
2. K4开灯，旋钮从低到高转动，观察亮度与日志 `[BRIGHT] source=POT target=.../1000`。
3. 快速来回转动后停住，确认最终值跟随，没有大量旧位置继续执行。
4. 旋钮不动时确认不会连续发送；上电不旋转也不应主动覆盖亮度。
5. K4关灯，转动旋钮，灯应保持关闭；再开灯后检查亮度应用。
6. 同时测试K4和其他按键，确认I²C事件与屏幕仍工作。

本次完成编译/编译期合并限频测试与副板哈希核对，未烧录、未实测旋钮控制灯泡。
